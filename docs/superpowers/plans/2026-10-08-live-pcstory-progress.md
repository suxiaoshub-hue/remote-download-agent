# PCStory 实时进度修复

目标：网页按 GID 显示 PCStory 下载页的实际状态、百分比和预计剩余时间。

根因：旧 Agent 在命令完成时冻结空目录路径，按文件长度推算进度；文件预分配与游戏更新总量使这种推算也不可靠。原有浏览器测试手工上报样本，没有覆盖 PCStory 读取。

方案：使用 Windows 标准 ListView/Header 只读消息读取 PCStory 下载列表。文件资源已确认存在 SysListView32 和 ID、状态、进度、更新量(MB)、剩余(MB)、速度列。验证目标可执行文件哈希，按列标题和 GID 匹配，不切换页面或点击鼠标。读取参数用目标进程临时内存，超时保留临时内存以防迟到消息，报错后停止本轮。

- [x] 添加列解析测试，涵盖暂停、2.97%、更新量不同于游戏大小、未知速度及格式歧义。
- [x] 添加 Windows 实际跨进程 ListView 接收程序和读取测试。
- [x] Agent 独立进度线程每 5 秒读取当前活动任务，支持重启恢复和采集失败诊断；删除目录大小采样。
- [x] 服务端鉴权、样本新鲜度验证，使用剩余量/速度计算 ETA；未知值保留未知。
- [x] 网页显示两位小数百分比与实际状态，暂停与旧样本不显示 ETA。
- [ ] 全量测试、浏览器回归、Windows 控件读取测试、代码复核和 GitHub Windows/Linux 编译。

真实 PCStory 控件能否返回所有绘制字段，仍需用户测试机验证；CI 只证明标准控件读取和端到端上报正确。缺少字段写入 pcstory-progress.json 和 agent.log，不伪造 0% 或倒计时。

本地验证：37 项 Python 测试通过；Chrome 浏览器验证两级页面、真实样本显示 2.97%、暂停保持百分比、119 秒旧样本隐藏 ETA、库存完成覆盖采样状态。代码复核修正样本时间新鲜度和终态优先级问题。Windows 编译与跨进程控件验证由新提交 Actions 执行。
